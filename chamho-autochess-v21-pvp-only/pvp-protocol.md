# PvP 서버 진행 방식 — 메시지 규격 (서버: `server.js` + `pvp-game.js`)

> **실제 브라우저 테스트는 하지 못했습니다.** 서버는 Node에서 가짜 소켓과 실제 WebSocket(`ws`)으로, 클라이언트(`public/pvp.js` + 원본 `index.html`)는 가짜 화면(DOM/canvas 스텁)으로 Node에서 실행해 두 클라이언트를 서버에 연결한 한 판 통째로 검증했습니다. **실제 화면에서 어떻게 보이는지(그림, 터치, 레이아웃)는 확인하지 못했습니다.**
> 이 방식은 기본으로 꺼져 있습니다. 환경변수 `PVP_SERVER_AUTH=1`을 줄 때만 켜지고, 끄면 기존 중계 방식 그대로 동작합니다(테스트로 확인). 문제가 있으면 이 변수를 지우면 바로 예전 방식으로 돌아갑니다.

## 켜는 법
- 로컬: `PVP_SERVER_AUTH=1 npm start`
- Render: Environment에 `PVP_SERVER_AUTH` = `1` 추가 후 재배포. (클라이언트 `public/pvp.js`는 이미 서버 진행 방식에 대응하도록 바뀌어 있고, 서버가 `matched.auth`로 알려 줄 때만 새 경로를 씁니다.)
- 시간 조정(테스트용): `PVP_PICK_MS`(기본 30000), `PVP_PLACE_MS`(기본 30000), `PVP_TICK_MS`(기본 50)

## 기본 원칙
서버가 두 플레이어의 모든 상태(부대, 증강, 목숨, 3장 제시 목록, 기물 지정 대기)를 갖고, 클라이언트는 **요청만** 보냅니다.
요청이 규칙에 맞지 않으면(제시되지 않은 증강, 내 진영이 아닌 칸으로 이동, 지정 대기 중 레디 등) 거절하고 상태를 바꾸지 않습니다.

## 로비 (기존과 같음)
`list`, `create {name}`, `join {id}`, `leave` → `rooms`, `created`, `matched {id, opp, auth}`. `auth: true`이면 서버 진행 방식.

## 클라이언트 → 서버 (게임 중)
| 메시지 | 언제 | 설명 |
|---|---|---|
| `{t:'pick', id}` | 증강 선택 단계 | 제시된 3장 중 하나 |
| `{t:'reroll'}` | 증강 선택 단계 | 라운드당 1회, 3장을 다시 뽑음 |
| `{t:'unit', c, r}` | 배치 단계, `me.pend`가 있을 때 | 기물 지정(말, 거대화, 결속 등)에서 칸 선택 |
| `{t:'move', from:[c,r], to:[c,r]}` | 배치 단계 | 배치 이동. 내 진영(5~9줄)만 |
| `{t:'ready'}` | 배치 단계 | 레디. 지정 대기 중이면 거절 |
| `{t:'negotiate'}` | 전투 중 | 협상(`neg` 증강 횟수만큼) |

## 서버 → 클라이언트
- **`state`** (단계가 바뀌거나 내 상태/상대 배치가 바뀔 때마다): `{phase:'place'|'pick'|'wait'|'battle', deadline, now, me:{roster, aug, lives, round, kami, negMax, flash, offer, rrUsed, lose, pend:{k,step,got,elig}}, opp:{roster(내 시점으로 180도 회전됨), augs, lives, ready, phase}}`
  - `deadline`은 서버 시각(ms)이므로 `deadline - now`로 남은 시간을 계산하세요.
  - `me.pend.elig`는 지정 가능한 칸 목록(강조 표시용)
- **`b_start`**: `{seat:0|1, id, seed, tick(ms), flip:{x,y}, init:{us:[유닛...], aux}, me, opp}` — 전투 시작. `seat`가 1이면 서버 좌표가 상대 시점이므로 **클라이언트에서 180도 뒤집어 그려야 합니다.**
- **`b_frame`** (초당 20회): `{id, i, d:[[유닛번호, {바뀐 필드}], ...], ev:[이벤트...], a?:{aux 전체}, last?}`
  - 시간 `t = (i+1) × 0.05`초
  - 유닛 필드는 `team, type, c, r, c0, r0, x, y, hp, mx, ...`. 새 유닛은 `d`에 전체 필드로 나타남
  - 이벤트: `{k:'txt', x, y, s, c}`(떠오르는 글자), `{k:'end', res}`, 그 외는 이펙트(`k:'w'|'x'|'b'|'p'|'h'|'l'|'a'|'fist'|'sa'|'fl'`). `a`/`b`는 `{u:유닛번호}` 또는 `{x,y}`
  - **`seat` 1이면 뒤집을 것:** `x' = flip.x - x`, `y' = flip.y - y` (`b_start.flip` = `{x:360, y:440.5}`, 화면 높이 470이 아님에 주의), `c' = 5-c`, `r' = 9-r`, `c0`/`r0`도 같게, `team`은 0↔1 교환. 이벤트의 `x,y,c,r`와 `a`/`b`의 `{x,y}`도 같은 변환
- **`b_end`**: `{res:'win'|'lose'|'draw'}` (받는 사람 기준). 1.3초 뒤 서버가 다음 단계로 넘어감
- **`over`**: `{win, reason}` — 한쪽 목숨이 0이 되면 종료
- **`opp_left`**: 상대가 나감 (남은 사람 승리)
- **`err`**: `{msg}`

## 진행 규칙 (원본 `finish()`/타이머와 같음)
1. 매칭 → 둘 다 **배치 30초**. 시간이 끝나면 지정 대기를 풀고 자동 레디. 둘 다 레디하면 즉시 전투.
2. 전투는 서버가 시드(서버가 정함)로 **끝까지 미리 계산**해 두고 20프레임/초로 전송. 협상이 들어오면 같은 시드로 다시 계산해 아직 안 보낸 프레임만 교체.
3. 결과: 승자는 임시 유닛 제거, 패자는 목숨 −1. 무승부(드래곤)는 같은 라운드를 다시 배치.
4. **증강 선택 30초**: 승자는 일반 선택(라운드+1, 무료 보병 지급), 패자는 패배 보상 선택(라운드 유지). 시간이 끝나면 제시된 3장 중 무작위 자동 선택.
5. 선택 후 다시 배치 30초. 한쪽 목숨이 0이 되면 `over`.
- **원본과 다르게 한 것:** 원본의 "15라운드 승리 시 게임 종료"는 PvP에서는 적용하지 않았습니다(목숨으로만 종료). 필요하면 알려 주세요.

## 알려진 한계
- 전투 계산(미리 계산)은 한 판에 평균 약 90~150ms, 최악 약 430ms 동안 서버가 다른 일을 못 합니다(Node 한 줄 처리). 동시 방이 많으면 지연이 보일 수 있습니다. 필요해지면 계산을 별도 스레드(worker)로 옮길 수 있습니다.
- 방 정보는 서버 메모리에만 있어서, Render 무료 플랜이 잠들거나 재배포되면 진행 중인 게임이 사라집니다(재접속 복구 없음).

## 클라이언트(`public/pvp.js`)가 하는 일 (서버 진행 방식일 때만)
- 서버의 `state`를 원본 화면 코드가 읽는 `st`(부대, 생명, 증강, 지정 대기)에 채우고, 원본 `draw()`/`hud()`로 그립니다. `st`는 새로 만들지 않고 값만 바꿉니다.
- `b_start`/`b_frame`으로 `B`(전투 상태)를 만들고, 2번 플레이어는 좌표/칸/팀을 뒤집어서 내 부대가 항상 아래쪽에 오게 합니다. 서버가 보낸 값 사이는 부드럽게 따라가고, 이펙트와 떠오르는 글자는 수명만 줄입니다(전투 계산은 하지 않음).
- 원본 함수 6개를 서버 진행 중에만 비활성화합니다: `upd`(전투 계산), `fuseCheck`(융합 규칙), `turnTimeout`(시간 초과), `openPick`/`renderPick`(증강 뽑기), 클릭 핸들러(로컬 이동/지정) — 서버 진행이 아닐 때는 원래 함수로 위임합니다.
- 증강 선택 창은 서버가 준 3장으로 그리고, 카드 클릭은 `pick`, 리롤은 `reroll`, 보드 클릭은 `unit`/`move`, 레디는 `ready`, 협상 버튼은 `negotiate` 요청만 보냅니다. 일시정지(버튼, 스페이스/P)는 막습니다.
- 남은 시간은 서버의 `deadline`으로 표시합니다. 서버 진행 중에는 원본 타이머가 글자를 못 바꾸도록 막았습니다.

## 알려진 한계 (클라이언트)
- 이펙트 중 방향 값이 있는 것(예: 주먹 `fist`의 `f`)은 2번 플레이어 화면에서 방향이 뒤집히지 않았을 수 있습니다. 큰 유닛(2×2)의 `c,r` 기준점도 뒤집을 때 근사값입니다(그리는 위치는 `x,y`를 쓰므로 영향 적음).
- 서버 프레임은 20회/초라서 원본(60fps 계산)보다 움직임이 약간 덜 부드러울 수 있어 클라이언트에서 보간합니다.
- `카미카제` 버튼(`kb`)과 필드를 바꾸는 증강(PvP 제외 목록)은 PvP에서 나오지 않으므로 대응하지 않았습니다.

## 메뉴 (PvP 전용)
- **AI 전투 버튼을 없앴습니다.** 시작 메뉴는 "PvP 대전" 하나뿐이고(게임 모드/고난 모드 선택도 나오지 않음), 게임 중 메뉴는 "계속하기 / 대전 나가기"입니다(대전 중이 아닐 때만 "PvP 대전" 추가). 예전의 "처음부터 (AI 전투)"는 "대전 나가기"로 바꿨습니다.
- 상대가 나가거나 연결이 끊겼을 때 예전처럼 AI와 계속 싸우는 대신, 안내 창과 "메인 메뉴" 버튼이 뜹니다(서버 진행 방식과 기존 중계 방식 모두).
- 이 변경은 `public/pvp.js`에서만 했습니다. `public/index.html`(원본)은 그대로이고 안에 AI 전투 코드가 남아 있지만 화면에서는 들어갈 수 없습니다.
